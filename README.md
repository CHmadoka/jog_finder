# job_finder

通过**已登录浏览器的招聘网站账号**(Boss直聘 / 前程无忧 / 猎聘),自动按筛选条件抓取岗位详情,
经"HR 活跃度 / 最近发布"过滤与数据库查重后存入本地 SQLite,并自动在备注中写明"不符合原因"。

## 功能特性

- **接管真实浏览器**:通过 Chrome/Edge 的 CDP 调试端口连接,登录态天然保留、指纹真实、风控风险低
- **三平台独立抓取**:每个平台同时最多一个抓取任务,平台之间互不影响
- **"档位"式岗位筛选**:一个标签名(如"Java后端")+ 多个具体岗位词条(如 Java、Java开发、服务端),一次任务跑全部词条
- **活跃度过滤**:只入库 HR 最近活跃 / 岗位最近发布的岗位(阈值可配置,默认 7 天)
- **自动查重**:`(平台, 岗位ID)` 唯一键,已入库岗位不重复保存,有变化则同步更新
- **自动备注**:关键词规则 + 行业偏好分析职位描述,把"岗位要求不符 / 加班 / 压力大 / 出差驻场"等原因写入备注
- **本地 Web 界面**:档位与条件管理、任务启停与实时进度、岗位浏览(分页/筛选/搜索)、详情查看、Excel 导出

> 搜索与判定的完整规则(搜什么、怎么翻页、凭什么入库、备注怎么生成)见
> **[搜索与判定规则](#搜索与判定规则)** 一节。

## 环境要求

- Windows 10/11,Python 3.11+
- 本机安装 Chrome 或 Edge

## 安装

```powershell
cd D:\git_repo\job_finder
python -m venv --copies .venv        # 若默认方式报 Permission denied,保留 --copies
.venv\Scripts\python -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r requirements.txt
Copy-Item .env.example .env          # 按需修改配置
```

无需安装 Playwright 自带浏览器(只用 CDP 接管系统 Chrome/Edge)。

## 配置说明(.env)

| 配置项 | 说明 |
|---|---|
| `BROWSER_PATH` | 浏览器 exe 路径;留空则自动探测 Chrome/Edge 常见位置 |
| `CDP_PORT` | 调试端口,默认 9222 |
| `BROWSER_PROFILE_DIR` | 专用浏览器 profile 目录(登录态保存在这里) |
| `HR_ACTIVE_DAYS` / `JOB_PUBLISH_DAYS` | 活跃度窗口天数,默认 7(本仓库 `.env` 配的 30) |
| `DELAY_MIN/MAX`、`MAX_PAGES_PER_TASK` | 防风控节奏与单任务页数上限 |

> Chrome 136+ 禁止对默认用户目录开启 CDP,因此本工具使用**独立 profile**:
> 首次拉起的浏览器窗口中,请手动登录三个平台,登录态会持久保存,之后无需重复登录。

## 使用流程

**一键启动**:双击项目根目录的 **`启动.bat`** —— 自动检查服务是否在运行、按需初始化环境、
以最小化窗口启动服务并自动打开 `http://127.0.0.1:8765`(关闭 job_finder-server 控制台窗口即停止服务)。

也可以手动启动:

```powershell
.venv\Scripts\python -m app.main
```

**抓取操作(左栏,无需预先建条件)**:

1. 点选**顶栏 logo 右侧**的平台徽标(Boss直聘 / 前程无忧 / 猎聘)
2. 选择**岗位档位**(一次任务自动跑该档位的**全部词条**,对齐多关键词批量采集)
3. 选城市(可多选,留空=全国)、填每词条页数、按需填薪资范围 → 点**开始抓取**
4. 顶栏中心实时显示:当前词条/城市组合进度、发现/入库/跳过计数、跳过原因明细;
   左栏「最近任务」卡片(紧随抓取卡下方)记录历史任务
5. 需要复用的配置点"存为条件";已存条件可在"筛选条件"里编辑(条件必须关联岗位档位,
   因为词条只来自档位)

**结果浏览(右栏)**:岗位表格含行业列与"契合/不符"备注列;点击行看详情
(职位描述、HR活跃、技能标签);支持按匹配情况筛选、搜索、导出 Excel、"清空岗位库"。

## 搜索与判定规则

抓取分两层:**搜索**(决定去平台搜什么、能捞回哪些岗位)和**判定**(决定哪些岗位
能入库、给什么备注、标记契合还是不符)。下面按这两层说明,细节全部对应到源码。

### 一、搜索:一次任务搜什么

一次抓取任务在启动时把"岗位档位 + 城市"展开成搜索组合,**逐组合串行检索**:

```
搜索组合 = 档位的全部词条 × 选中的城市
```

- **词条**:只能来自所选**岗位档位**(一个标签名 + 多个词条,如"Java后端":Java、
  Java开发、服务端)。任务会跑档位的**全部**词条,没有"只跑其中一个"的入口。
  档位没有词条时启动即报错。
- **城市**:多选,留空表示**全国**。城市必须命中平台的城市代码表,未收录的城市在
  启动前就被拒绝(不会悄悄回退全国)。每个城市与每个词条各组合一次。
- 举例:"Java后端"(3 个词条)× 上海、杭州(2 个城市)= **6 个组合**,
  按顺序逐个检索,每组合之间插入人类化随机延迟以降低风控风险。

任务状态卡会显示组合进度(`任务组合 3/6:「Java开发」@杭州 开始`),
结束时的消息形如 `完成:3 个词条×2 个城市,发现 120,新入库 78,跳过 42(...)`。

### 二、搜索:单个组合内怎么翻页

每个组合内按平台适配器分页检索,逐页解析岗位列表:

- **页数上限**:由"每词条最多翻页数"控制(界面可设,默认取 `MAX_PAGES_PER_TASK`)。
- **提前翻完**:平台明确没有下一页时立即停止。
- **整页都是已知岗位**时继续往后翻(说明这一页只是旧的,后面可能还有新的)。
- **列表阶段就过滤薪资**:配置了薪资范围时,列表解析出的薪资范围与配置**完全无交集**
  的岗位直接丢弃,不打开详情页(省一次请求 = 少一次风控暴露)。
  薪资文本无法解析时**不误杀**,照常进入详情。

  薪资比较的细节(`app/platforms/common.py`):

  | 薪资文本 | 解析结果(月薪 K) |
  |---|---|
  | `15-25K·16薪` | 15–25(16 薪另存 `salary_months`) |
  | `1.5-2.5万` | 15–25(万 = 10K) |
  | `20K` | 20–20 |
  | `30-60万/年` | 25–50(年薪按 ×10/12 折算到月) |
  | `面议`、`元/天` | 无法解析 → **不过滤** |

  配置范围单边可缺省(`20,` = 只要 ≥20K;`,12` = 只要 ≤12K),
  分隔符宽容(`-` `~` `～` `，` 都行),比较时**部分重叠也算通过**
  (岗位 15–25K、配置 10–20K → 保留)。

- **详情前查重**:已入库的岗位不再打开详情页。这是风控的主要成本来源,跳过可显著省钱。

平台差异(2026-11 实测校准):

| 平台 | 检索方式 | 备注 |
|---|---|---|
| Boss直聘 | 接口直连 `/wapi/zpgeek/search/joblist.json` | 明文薪资/行业/HR在线;薪资字体反爬(PUA 字形)用 canvas 模板匹配解码;详情 URL 携带 `securityId`/`lid` 防重定向 |
| 前程无忧 | 载体页停在 `we.51job.com` 搜索页,列表数据走页内 fetch `/api/job/search-pc` 接口直连 | 冷启动首屏捕获**页面自身的签名请求**作为第一页(跨域冷启动后立刻 fetch 会被软风控以"合法空列表"拒绝);列表自带完整职位描述/精确发布时间/数值薪资/公司行业/HR在线,常规情况**不开详情页**;翻页 pageSize 与页面自身请求对齐(20/页),按接口 `totalcount` 提前结束;活跃度判定走精确发布时间 |
| 猎聘 | 搜索接口有签名墙(页内直发被拒 `-1400`),改为**导航驱动 + 响应监听**:goto 搜索页 URL,捕获页面自己发出的 `pc-search-job` 签名响应(结构化 jobCardList),DOM 卡片解析兜底 | 列表含公司行业/规模/融资阶段/HR活跃文案("1天前在线");职位描述需逐岗打开详情页(schema.org JobPosting JSON-LD 优先);搜索结果会混入外地推荐岗位与 `/a/` 文章卡(后者列表阶段即跳过);风控页为 `safe.liepin.com` 短信验证(`账号行为异常`) |

三个平台共同的高标准处理:详情/接口随机 2~8s 间隔;验证页特征即时判定(AntiBot 中止任务,
绝不重试连发);详情落地 URL 必须含岗位 ID(防重定向写错数据);页面被反自动化清空
(blank)时标记跳过;解析失败自动存快照到 `data/snapshots/`。

### 三、判定:单个岗位能不能入库

每个岗位(已解析完详情)按以下顺序判定,**任一步失败即跳过并计入跳过原因**:

| 顺序 | 判定 | 结果 |
|---|---|---|
| 1 | 详情页跳回首页/异常跳转 | 视为**已下线**,跳过(`已下线/失效`) |
| 2 | 详情页被反自动化清空 | 跳过并写入异常面板(`被平台拦截`) |
| 3 | 数据库查重 `(平台, 岗位ID)` | 已存在则**只同步有变化的字段**,不重复插入(`已存在`) |
| 4 | **活跃度窗口** | 超出窗口则**不入库**(`活跃度/新鲜度窗口`) |
| 5 | 行业偏好 + 关键词规则 | **不拦截**,只写入备注 |

同一轮任务内,同一岗位被多个词条搜出时由内存去重(`同轮重复`),只处理一次。

### 四、活跃度窗口(唯一会拒绝入库的判定)

`app/filter/activity.py` 的 `within_active_window()`。优先看 **HR 最近活跃**,其次看
**岗位发布时间**,阈值来自 `.env` 的 `HR_ACTIVE_DAYS` / `JOB_PUBLISH_DAYS`(默认 7 天,
本仓库 `.env` 实际配的是 30 天)。

平台给的活跃时间是**模糊文案**,所以判定按后缀区分方向:

| 存储后缀 | 含义 | 判定方式 |
|---|---|---|
| `…后` | 真实活跃**不早于**该时刻(如"本周活跃") | 估算值 + 1 分钟容忍 ≥ 窗口下界即通过 |
| `…前` | 真实活跃**不晚于**该时刻(如"长期未活跃") | **保守直接判超窗** |
| `…活跃` | 今日/昨日活跃 | 按该日 00:00 与窗口比较 |
| 无后缀 | 约精确时刻(如"N天前活跃") | 按普通时刻比较 |

- HR 活跃字段缺失时,退回用发布时间判断;
- **两个字段都缺失时不误杀**,照常入库(留给人工判断);
- 加 1 分钟容忍是因为时间做了分钟级截断(最多丢 59 秒),避免窗口边界被误杀。

### 五、行业偏好(只写备注,不拦截)

`app/filter/__init__.py` 的 `evaluate_job()`。筛选条件里可配两组行业关键词:

- **避开行业**(如金融、电商、游戏)
- **优先行业**(如制造业、医疗、学校)

判定顺序是 **避开优先于优先**:

| 情况 | 备注写入 |
|---|---|
| 行业命中避开列表 | `不符: 行业不符: 电子商务(需避开「电商」)` |
| 未命中避开,配了优先列表**且命中** | `契合: 行业契合: 医疗服务` |
| 未命中避开,配了优先列表但**没命中** | `不符: 行业非优先列表: XX` |
| 行业字段为空 | 不判定(不误杀) |

**行业名匹配允许字间跳字**:直接子串匹配有语义陷阱——"电商"不是"电子商务"的
连续子串("子"字隔开)。因此关键词按字拆分、允许中间最多隔 2 个字:
"电商" → `电.{0,2}商`,可命中"电子商务"。

> ⚠️ 这三类结果都只是**备注文字**,不会阻止入库。行业不符的岗位照样进库,
> 靠备注和界面筛选来区分。

### 六、关键词规则引擎(只写备注,不拦截)

`app/filter/rules.py`,纯正则扫描**标题 + 描述**,命中即往备注里追加一条。
共 11 条正文规则 + 2 条标题专属规则:

| 类别 | 触发信号(正则要点) | 备注话术 |
|---|---|---|
| 加班 | `996` `007` `大小周` `单休` `义务加班` `自愿加班` | 存在加班文化信号 |
| 压力 | `高强度` `压力大` `抗压能力强` `狼性` `内卷` `末位淘汰` | 工作强度/压力大 |
| 出差 | `长期出差` `经常出差` `全国出差` `出差频率高` | 长期出差 |
| 地点 | `驻场` `驻厂` `外派` `派驻` `异地办公` | 驻场/外派/异地 |
| 销售 | `提成` `业绩指标` `销售任务` `开单` `无底薪` `零底薪` | 含销售/业绩考核信号 |
| 风险 | `培训…费/押金/保证金` | 涉及培训收费/押金,谨慎 |
| 作息 | `倒班` `夜班` `两班倒` `三班倒` `轮班` `值班` | 需要倒班/值班 |
| 风险 | `30岁以上` `35岁以上` `不超过35` `年龄不超过` | 年龄限制信号 |
| 福利 | `五险一金…面议/转正后` | 社保公积金转正后才缴纳 |
| 方向不符 | `拉新` `地推` `电销` `陌拜` | 含销售/地推成分 |
| 性质 | `外包` `劳务派遣` `人力外包` | 外包/派遣性质(节奏取决于甲方) |
| 性质(仅标题) | `兼职` `实习` `小时工` `劳务` | 兼职/实习岗(非全职) |
| 级别(仅标题) | `资深` `高级` `专家` `架构` `首席` `总监` | 资深/管理级岗位 |

规则库可按需扩充,直接改 `_RULES` / `_TITLE_RULES` 列表即可。

> 早期版本还有一条「标题未直接命中档位词条」的软提示,现已**取消**——
> 词条本身只是检索用的搜索词,平台会返回大量同义/扩展结果,标题不含词条
> 并不代表岗位不相关,这条提示噪音大于价值。

### 七、契合 / 不符标记(抓取流程不产出)

`job.fit` / `job.fit_score` 字段保留,但**抓取流程不再自动写入**,新抓的岗位这两个字段为空。

- 数据来源改为**外部评估**(如 `推荐清单_黄浩岚.md` 那样基于已存数据离线打分后回写),
  不再由程序在抓取时实时计算,也不需要任何外部 API;
- 界面上,`fit` 为空的岗位**不显示契合/不符标签**,也不计入契合数/不符数统计;
- 「契合」统计条的悬停提示已相应说明。

如果希望新抓的岗位也有标记,可以基于已有数据离线评估后回写这两个字段,
或在 `evaluate_job()` 里接入自己的判定逻辑。

### 八、备注格式

规则命中项按类型拼接,`契合` 段在前、`不符` 段在后,段内用 `;` 分隔,段间用 ` | `:

```
契合: 行业契合: 医疗服务 | 不符: [压力] 工作强度/压力大;[加班] 存在加班文化信号
```

无任何命中时备注为空字符串。

### 九、完整判定链路

```
平台检索 → 列表解析
   ├─ 薪资范围无交集 → 丢弃(不开详情)
   └─ 已入库 → 跳过 detail(但保留 draft)
        ↓
      详情解析
   ├─ 已下线/被拦截 → 跳过
   ├─ (平台,岗位ID) 已存在 → 只更新变化字段
   ├─ 活跃度窗口外 → 不入库        ← 唯一会拒绝的判定
   └─ 通过 → 写入 job 表
        ├─ 行业偏好 → 备注
        └─ 关键词规则 → 备注
```

## 架构

```
Web界面(Vue3+ElementPlus) ──FastAPI──┐
                                     ├─ 调度器(每平台1并发) ─ 平台适配器(job51/boss/liepin)
SQLite(job_finder.db) ←──── 过滤引擎(活跃度/查重/规则备注)
                                     │
                              Playwright CDP ── 接管用户 Chrome/Edge
```

- `app/platforms/`:平台适配器。优先解析页面内嵌 JSON 与 JSON-LD,DOM 选择器兜底;
  所有选择器集中在 `selectors.py`,失效时先改这里
- `app/scheduler/`:任务调度、查重入库、跳过原因统计
- `app/filter/`:判定链路——`activity.py` 活跃度窗口(唯一会拒绝入库的)、
  `rules.py` 关键词规则(只写备注)、`__init__.py` 行业偏好与备注拼装
- 解析失败会自动把页面快照存到 `data/snapshots/`,便于修复选择器

## 常见问题

- **任务报"未登录"**:在自动拉起的浏览器窗口里登录对应平台,然后重新启动任务
- **Boss直聘提示"安全验证"**:程序会等待最多 120 秒,请在浏览器里手动完成滑块验证
- **列表解析不到岗位(0 条)**:平台改版导致选择器失效,查看 `data/snapshots/` 中的快照,
  调整 `app/platforms/selectors.py` 后重启服务
- **端口被占用**:修改 `.env` 中的 `PORT`(Web)或 `CDP_PORT`(浏览器调试端口)
- **岗位没有"契合/不符"标签**:该标记不再由抓取流程产出,需要外部评估后回写
  `job.fit` / `job.fit_score`;为空时不显示标签,也不计入两侧统计,详见
  [七、契合 / 不符标记](#七契合--不符标记抓取流程不产出)
- **大量岗位被判"不符"但没被拦掉**:行业偏好与关键词规则**只写备注、不拦截**,
