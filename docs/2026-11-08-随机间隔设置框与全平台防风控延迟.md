# 随机间隔设置框与全平台防风控延迟

日期:2026-11-08

## 需求

1. 所有平台在抓取时确保随机 3~8 秒间隔,避免风控。
2. 左栏「存入数据表」选择框下方新增"随机时间范围"设置框(下限/上限),并提供复位按钮。
3. 右值(上限)必须大于等于左值(下限)。
4. 任一数值低于 2 秒时,显示红字风控建议。

## 实现

### 前端(web/index.html + web/app.js)

- 「存入数据表」下方新增 **随机间隔(秒)** 双输入框(`el-input-number`,0.5~60,步长 0.5),
  标签行右侧带 **复位** 按钮(恢复默认 3~8 秒,轻提示反馈)。两种抓取模式(快速/已存条件)共用。
- `normalizeDelay()`:任一端变更后规整——空值回默认;右值 < 左值时右值自动抬回左值,
  保证"右值 >= 左值"恒成立。
- `delayRisk` 计算属性:任一端 < 2 秒时在设置框下方显示红字建议
  (⚠ 风控建议:间隔低于 2 秒请求过密,极易触发平台风控,建议保持 3~8 秒)。仅警告不拦截。
- `startTask()` 将 `delay_min/delay_max` 随任务请求提交。

### 后端

- `app/api/tasks.py`:`POST /tasks/start` 接收 `delay_min/delay_max`,透传调度器。
- `app/scheduler/runner.py`:
  - `start()` 规整范围(`utils.normalize_delay`:非法回退 config 默认 3~8、倒置自动交换)
    并写入任务快照;
  - `_run()` 启动时 `set_runtime_delay(platform, lo, hi)` 注册**平台级**运行时覆盖,
    进度区显示生效范围;词条组合间延迟改为 `human_delay(platform)`;
    `finally` 中 `clear_runtime_delay(platform)` 清除。
- `app/utils.py`:新增运行时延迟注册表(每平台同时仅一个任务,互不干扰);
  `human_delay(platform)` 支持平台级覆盖;新增 `detail_delay(platform)`
  统一三个平台的详情页间隔(原先各自内联 `config.DETAIL_DELAY_*`)。
- 三个平台适配器(boss/job51/liepin):详情页延迟改调 `detail_delay(self.id)`,
  全部 `human_delay()` 调用改为传平台 id;移除不再使用的 `random`/`config` 导入。

### 生效范围

任务级范围统一应用于:列表翻页间隔、词条组合间间隔、详情页访问间隔——
即**所有平台、所有页面动作**的随机间隔都在该范围内(默认 3~8 秒)。
`.env` 的 `DELAY_*` 与 `DETAIL_DELAY_*` 降级为兜底(脚本直调/未传参任务),
默认值统一为 3~8。

## 验证

- 冒烟:normalize_delay 倒置/非法/边界用例;注册 0.5~0.6 后 human_delay+detail_delay
  实测 sleep 1.05s(两次 ×~0.55s),范围生效。
- `unittest discover tests`:95 个测试全部通过。
