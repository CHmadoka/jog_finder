# 来源词条记录与命中标签修复

日期:2026-11-07

## 用户反馈

1. "德诚珠宝集团有限公司"这条数据没有任何高亮匹配词条;
2. 有些岗位描述中高亮词条有多个,顶部黄色标签却只有一个。

## 根因

1. **顶部标签漏判(bug)**:`hitKeywords` 构造样本时标题做了小写转换但
   **描述没有**——英文词条(如 Excel)在描述里命中却进不了标签,而描述
   内的 `<mark>` 高亮走的是全小写逻辑,正常命中 → 表现为"描述多个高亮、
   顶部只剩中文词条一个标签"。
2. **来源词条缺失**:岗位真正"匹配"的词条是**搜索来源**(由哪个词条的
   搜索结果中抓出),此前未记录——像"业务支持兼数据分析"(德诚珠宝)
   描述写的是"数据的整理、汇总和分析处理",不含"数据处理"连续子串,
   纯文本匹配无命中 → 无任何高亮。

## 实现

- **新列 `job.source_keyword`**(entities + `_NEW_COLUMNS` 迁移):
  任务循环把当前词条传入 `_process_one` → 入库/更新时写入
  (已存在岗位被其它词条任务再次发现时随"最后更新"语义刷新)。
- **旧数据一次性回填**(user_version=3 守卫):取标题/描述中命中的
  **第一个词条**(确定性依据,非猜测)。实测 771 条中 588 条可回填,
  183 条文本无命中留空——这些是平台搜索扩展返回的相关岗位,旧数据
  未记录来源无法确知;今后新抓取的都会实时记录,保证必有来源标签。
- **前端命中标签 = 来源词条 ∪ 文本命中**(去重):来源词条即使文本
  未出现也算匹配(描述换了说法但确由该词条搜出),悬停提示区分两种
  来源;并修复描述未小写的漏判 bug。

## 验证

- 68 项测试全部通过;py_compile / node --check 通过;
- 回填效果只读预演:588 可回填 / 183 留空(见上)。

## 备注

- 需重启服务生效:启动时自动加列 + 回填;前端刷新即可。
