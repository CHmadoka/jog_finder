# 移除「限定词条」功能

日期:2026-11-07

## 背景

「限定词条」有两个入口,其中条件管理弹窗里的那个**从未生效**:
`_db_load_condition()` 把 `flt.keyword` 读进了 `f_kw` 变量,但 `start()`
拼 `kw_list` 时只看前端显式传的 `keyword` 和档位词条,`f_kw` 从头到尾没被用过。
而前端走「已存条件」模式时只发 `{filter_id, salary, table_id, max_pages}`,
从不传 `keyword`。结果是存了限定词条照样按设置全部词条跑,条件摘要却把它
显示出来,容易误以为生效。

用户判断该功能整体无用,要求完全移除。

## 改动

**前端**
- 左栏快速抓取:`限定词条` 输入框及其「清除」链接删除;`canStart` 改为
  仅要求选中岗位设置,提示语相应改为「请先选择岗位设置」;启动请求体不再带
  `keyword` / `all_keywords`。
- 条件管理弹窗:「限定词条」表单项、表格「词条」列删除;条件摘要里的
  「词条」行删除;`filterForm.keyword` 字段与相关读写删除。
- 条件保存新增「请选择岗位设置」校验——词条只能来自岗位设置,未关联设置的
  条件无法启动抓取,提前拦下比事后报错好。
- 岗位设置下拉的 placeholder 由「选择设置(一次跑其全部词条)」简化为
  「选择设置」(已无"部分词条"的可能,不必解释)。

**后端**
- `Scheduler.start()` 去掉 `keyword` / `all_keywords` 参数与分支逻辑,
  词条统一取所选设置的全部;无词条时报明确错误
  「所选岗位设置没有词条,请先在「岗位设置」中添加」。
- `_db_load_condition()` 返回值去掉 `f_kw` 一项。
- `/tasks/start` 不再读取 `keyword` / `all_keywords`;
  `SearchFilterIn` / `StartTaskIn` 删除 `keyword` 字段。
- `SearchFilter.keyword` 列移除,`_migrate_columns()` 新增 `_DROP_COLUMNS`
  一次性删除该列(幂等,SQLite 3.35+ 支持 `ALTER TABLE ... DROP COLUMN`)。
- 条件创建/更新的接口校验:必须带 `gear_id` 且设置存在。

## 保留不动

- `crawl_task.keywords`、`job.keyword`、`job.source_keyword` **不是**本功能
  的一部分,分别用于任务记录、详情页命中高亮,保持原样。
- 岗位设置自身的多条词条能力不受影响,抓取仍按设置的全部词条逐一检索。

## 验证

- 68 项单元测试全绿;`node --check` 与 py_compile 通过。
- 数据库迁移实测:旧库 `search_filter.keyword` 被删除,771 条岗位数据完好。
- 接口实测:条件创建响应不再含 `keyword`;无条件词条时启动返回 400 并给出
  明确文案;界面创建/编辑/删除条件全流程无报错。
- 界面实测(1500×950 @2x 无头浏览器):左栏与条件弹窗均无「限定词条」痕迹,
  未选设置的保存被「请选择岗位设置」拦下。

## 备注

- 后端有改动且 `reload=False`,需重启服务生效;前端强刷(Ctrl+F5)即可。
