# 2026-11-06 登录检查前移与打开落点诊断

## 背景

用户反馈:未登录时"打开原始岗位页面"也提示"需要安全验证"(误导);抓取前应先检查登录。

实测佐证:未登录状态下打开 Boss 岗位页,部分页面被平台 302 到 `_security_check=...`
验证页(浏览器现存标签可证),旧逻辑一律提示"完成滑块验证"——但根因是未登录,
完成滑块也无济于事。

## 变更

1. **抓取前登录预检查(前端拦截)**:新增 `POST /api/tasks/check_login`;
   点击「开始抓取」先探测目标平台登录态,未登录直接弹窗提示"请先在浏览器中登录",
   不再发起任务(任务内的登录检查仍保留为兜底)。
2. **打开落点诊断** `browser_manager.diagnose_open`(jobs/events 两个 open 端点接入):
   - 落点 URL 含 `login / passport / /web/user/` → 直接判"未登录"(零导航);
   - 其余疑似验证页且平台空闲 → 用适配器 `is_logged_in` 二次确认;
   - 平台任务运行中不做导航式探测(避免打断载体页),维持原验证提示。
   命中未登录时返回 `need_login`,前端弹"未登录"指引而非"安全验证"。
3. **Boss 登录判定修正**:游客态搜索接口也可能返回 `code=0`,不能作为已登录依据;
   判定顺序改为 页面登录UI(头像→已登录 / 登录入口→未登录)优先,
   接口 code 仅作 UI 不可判时的兜底。

## 验证

- 实测 `check_login(boss)` 返回 `logged_in: false`,与当前浏览器未登录状态一致;
- CDP 原生枚举标签页确认存在 `_security_check` 落点,诊断逻辑可正确区分;
- unittest 64 项全部通过。
