# 详情操作按钮置顶 + 关联/扩展词条分色显示

日期:2026-11-07

## 需求

1. 岗位详情的「在已登录浏览器打开」「删除」按钮移到顶部标题下方,持续置顶;
2. 没有完全匹配(文本精确出现)词条的岗位,以图标显示"关联/扩展词条",
   用颜色与精确命中区分。

## 实现

1. **按钮置顶**:移入详情抽屉 `#header` 插槽(header 天然不随内容滚动),
   标题下方一行两个按钮;原 body 底部按钮区删除。
2. **两态命中标签**(`web/app.js` hitKeywords / `web/index.html` 模板):
   - **精确命中**(黄色 warning):词条出现在标题或描述文本中;
   - **关联/扩展**(蓝色 primary + Connection 关联图标):来源词条
     (source_keyword)存在但文本未精确出现——平台按词条扩展返回的
     相关岗位;悬停提示说明两种含义。
3. **回填策略升级**(database.py,user_version=3,启动时一次性):
   - 优先:标题/描述中命中的第一个词条(精确);
   - 兜底:与标题"最长公共子串"最长的任务词条作为关联词条
     (公共子串 <2 字视为无关不硬凑)。
   - 实测 771 条:精确回填 588 + 关联回填 154 = 742(96%)有标签;
     余 29 条(如"文职岗 助理缺两位")与所有词条公共子串均不足 2 字,
     无据可填保持留空——新抓取数据实时记录来源词条,必有标签。
   - `_lcs_len` 启发式函数(小文本,仅标题参与,毫秒级)。

## 验证

- 68 项测试全部通过;py_compile / node --check 通过;回填覆盖率只读预演见上。

## 备注

- 回填/加列需重启服务生效;前端两态显示刷新即可。
- 关联词条是启发式恢复(旧数据未记录来源),语义上正确但非事实精确;
  新数据的 source_keyword 为抓取时实际词条,准确无误。
