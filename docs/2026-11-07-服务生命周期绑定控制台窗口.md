# 服务生命周期绑定控制台窗口

## 问题

双击 `启动.bat` 后弹出 `job_finder-server` 控制台窗口运行服务。关闭该窗口后,
服务有时仍在后台运行(`http://127.0.0.1:8765` 依旧可访问),端口被占用,
再次双击 `启动.bat` 只会走"已在运行"分支,无法通过关窗口停止服务。

## 原因

`启动.bat` 以 `start "job_finder-server" cmd /c "...python -m app.main & pause"`
弹出独立控制台,进程链为:

```
cmd.exe(窗口宿主) → .venv\Scripts\python.exe(启动器壳) → 基础解释器 python.exe(服务)
```

部分终端宿主(如 Windows Terminal)关闭窗口时只终止其直接子进程 cmd.exe,
两个 python 进程会成为孤儿继续监听端口。

## 修复

`app/main.py` 新增 `_install_console_binding()`(仅 Windows,在 `main()` 单例守卫后调用):

1. **`SetConsoleCtrlHandler`**:收到 `CTRL_CLOSE/LOGOFF/SHUTDOWN` 立即 `os._exit(0)`,
   避免优雅关闭流程(lifespan 清理)拖过系统 5 秒宽限期;
2. **守护线程轮询 `GetConsoleProcessList`**:启动时记录控制台挂载进程数(通常为 3),
   一旦数量减少即认为宿主/壳进程已死,整个服务进程树立即退出(启动器壳随子进程退出)。

无控制台的分离启动(计划任务/服务方式)不启用守卫,避免误杀正常后台服务;
Ctrl+C 不受影响,仍走 uvicorn 优雅关闭。

## 验证

以同款 `cmd /c` 方式拉起服务 → 健康检查通过 → 强杀 cmd 壳进程(模拟 WT 只杀直接子进程):

- 日志依次出现 `控制台生命周期绑定已启用(初始挂载 3 个进程)` 与
  `控制台窗口已关闭,服务进程退出`;
- 约 3 秒内两个 python 进程全部退出,8765 端口释放。

需重启服务生效(运行 `启动.bat`)。
