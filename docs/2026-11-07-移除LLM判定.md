# 移除 LLM 判定与「标题未命中词条」软提示

日期:2026-11-07

## 背景

用户判断:**契合判定可以直接用已存数据离线评估**,没必要在抓取流程里额外接 LLM。
同时取消「标题里不含档位词条时写入`标题未直接命中档位[xx]词条`」这条软提示——
平台会按词条返回大量同义/扩展结果,标题不含词条并不代表岗位不相关,噪音大于价值。

经确认:`fit` / `fit_score` 字段**保留但抓取流程不再产出**(恒为空),
契合/不符标记改由外部评估回写。

## 改动

**删除**
- `app/filter/llm_analyzer.py` 整个模块(LLM 客户端、prompt、JSON 解析);
- `app/filter/__init__.py` 里的 LLM 分支、`fit` / `fit_score` 字段、
  以及「标题未直接命中档位[xx]词条」软提示及其清除逻辑;
- `app/config.py` 的 `LLM_API_BASE` / `LLM_API_KEY` / `LLM_MODEL` 与 `llm_enabled` 属性;
- `.env.example` 与 `.env` 中的 LLM 配置段;
- `requirements.txt` 的 `openai` 依赖;
- `/api/health` 响应里的 `llm` 字段。

**调整**
- `evaluate_job()` 由 `async` 改为**同步**(不再有 await),签名简化为
  `evaluate_job(draft, extras=None)`——`gear_name` / `keywords` 原本只服务于
  那条软提示和 LLM prompt,一并去掉;
- 调度器调用处同步修改,`_db_insert_job` 显式写 `fit=None, fit_score=None`;
- 前端顶栏健康文案由「LLM 备注已启用 / 规则备注(未配置 LLM)」改为固定「规则备注已启用」;
- 统计条「契合」悬停提示改为说明标记由外部评估写入;
- 实体注释由「LLM/规则判定」改为「外部评估写入」。

**保留不动**
- `job.fit` / `job.fit_score` 列**保留**(外部评估回写用,已入库的 771 条数据不受影响);
- `_REFRESH_FIELDS` 不含 `fit`,抓取时重复岗位更新**不会**覆盖外部写入的标记。

## 验证

- 69 项单元测试全绿(新增一条断言:标题不含词条时备注里不再出现该提示);
- `evaluate_job` 实测为同步函数,`FilterResult` 已无 `fit` / `fit_score` 字段,
  备注不含「标题未直接命中」;
- 服务重启后 `/api/health` 返回 `{"ok": true}`,前端显示「规则备注已启用」,无报错;
- 确认 `app/` 下已无 `llm` 相关模块(仅清掉了一个残留 `.pyc`)。

## 备注

- 后端改动且 `reload=False`,需重启服务;`openai` 依赖已从 requirements 移除,
  但已安装的包不影响运行,可留可卸。
