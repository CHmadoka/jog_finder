# 2026-11-07 猎聘与前程无忧抓取:实测校准 + Boss 级高标准

## 背景与结论

前程无忧(job51)与猎聘(liepin)两个适配器自 init 起就是按 2024 页面结构推测编写的
初版,**从未实测**(库中两平台数据为 0,且 runner 的"补全活跃"任务调用
`_parse_detail(..., should_stop=...)` 对二者必抛 TypeError)。本次接入已登录的专用
浏览器逐层实测,重写为与 Boss 同等高标准、且按平台差异分流的实现:

| 平台 | 实测结论 | 最终方案 |
|---|---|---|
| 前程无忧 | `we.51job.com` 为纯 SPA,页面**无任何内嵌 JSON**(旧版 `__SEARCH_RESULT__` 已失效);搜索数据走接口 `/api/job/search-pc`,精简参数即可直连(无需页面 URL 里的 `decode__1048` 风控 token) | 接口直连;**冷启动首屏捕获页面自身签名请求**作第一页数据 |
| 猎聘 | 同为 SPA 无 SSR 数据;接口 `pc-search-job` 有请求签名墙(页内直发 `-1400`);搜索结果混排外地推荐岗与 `/a/` 文章卡 | **导航驱动 + 响应监听**(页面自己发签名请求,`expect_response` 捕获),DOM 卡片兜底 |

## 前程无忧:接口直连版

- 列表:页内 fetch `search-pc`(pageSize=20,与页面自身请求对齐防翻页裂缝),
  按 `totalcount` 提前结束;条目自带**完整职位描述/精确发布时间/数值薪资/公司行业/
  HR 在线**,常规情况**零详情页请求**(单页一次请求,风控暴露面最小);
  描述缺失才开详情页兜底(JSON-LD + DOM)
- 冷启动陷阱(实测):从 `www.51job.com` 域冷启动后立刻页内 fetch 会被软风控拒绝
  ——返回合法的 `status=1` 但 `items=0`;修复为冷启动 goto 搜索页时
  `expect_response` 捕获页面自身的第一页响应(签名天然有效),fetch 仅作兜底;
  热启动(复用 we 域标签)直接 fetch
- 坑:`status` 是字符串 `"1"` 而非数字(初版比较 `!= 1` 把成功响应判为失败)
- 薪资:接口数值字段 `jobSalaryMin/Max`(元)优先参与范围过滤,文本兜底;
  翻页终止 = totalcount 耗尽 / 空页(空页且 total>0 时等待重试一次再定论)
- 活跃度:平台无 HR 活跃文案,判定走精确发布时间(`issueDateString`),
  `hrIsOnline` 存布尔

## 猎聘:响应监听版

- 列表:goto 搜索 URL → 捕获页面自身 `pc-search-job` 响应 → `jobCardList`
  (job/comp/recruiter 三段:标题/薪资/地区/经验学历/公司行业·规模·融资阶段/
  HR 名·职·活跃文案);DOM(`.jobCardPcContainer` 语义类名 + `data-nick` 钩子)
  兜底;`/a/` 非岗位卡在列表阶段静默跳过(否则每次白耗一次详情请求)
- 详情:逐岗打开,JSON-LD(schema.org JobPosting,实测描述完整)优先,
  `.job-intro-container` 兜底;`refreshTime`(YYYYMMDDHHMMSS)解析为发布时间;
  `imShowText`("1天前在线"/"当前在线")走统一活跃估算
- 风控(实测真实触发过一次):`safe.liepin.com/v/intercept/verifysms`
  ("账号行为异常"短信验证)→ AntiBot 立即中止任务,人工完成后重开任务续跑
  (已抓岗位查重跳过,零浪费)

## 公共修复

- `common.parse_salary_k` 混合单位 bug:"9千-1.5万"旧实现误算为 (15,90),
  现两侧单位分别换算为 (9,15)
- `utils.active_estimate_from_text` 补"N周前/N个月前/N(个)月前"与"当前/正在在线"
  规则(猎聘文案全谱覆盖)
- 两平台 `_parse_detail` 补 `should_stop` 参数(修复 runner 补全任务必崩)
- 登录检测统一为"页头 200px 内可见整词『登录/注册』入口"判定(防正文推广位误伤)
- 风控/落地校验/blank 检测/详情延迟(DETAIL_DELAY 2~8s)/快照与异常面板上报
  全面对齐 Boss 标准
- `selectors.py`:猎聘城市码表按实测 hotCities 重写(**全国=410**,旧表"000"是错的;
  杭州 070→070020、重庆 290→040 等多处纠错),城市集合收敛为已验证的 14 个
