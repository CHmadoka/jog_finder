# 平台 Logo 去红框(信号灯表达异常)与三平台防风控策略全面升级

日期:2026-11-08

## 需求

1. 触发风控后,平台 logo 不需要红色边框,只要信号灯变红。
2. 猎聘、前程无忧都在很短时间内触发了人机检查(验证码),三平台防风控策略全面升级。

## 改动一:logo 去红框,信号灯表达异常

- 删除平台 logo 按钮的风控红环(`.top-plat.st-error` 外圈 box-shadow 及其类绑定);
  完成态绿环保留。
- **信号灯变红保持并补全**:
  - 平台 logo 角标 badge 的 `err` 红态(原有)继续生效;
  - 顶栏状态区圆点新增 `err` 红态(带红色光晕):最近一次任务 error 时,
    该平台在状态卡的圆点变红(原先只有绿/灰两态,异常后只会变灰)。

## 改动二:防风控策略全面升级(三平台统一)

触发验证的直接诱因分析:猎聘每岗必开详情(单页 ~40 条连续导航)、前程无忧接口
fetch 节奏偏密,加上多平台并发时同一 IP 的**叠加请求率**没有总控。升级四层防线:

### 1. 跨平台全局导航闸(utils.global_nav_gate)

三个平台共用同一浏览器(同一出口 IP),各平台自身 3~8s 随机间隔叠加后总频率仍可能
过高。全局闸保证**任意两次主动请求(goto/接口 fetch)之间至少间隔 1.5~3 秒(随机)**,
与各平台自身间隔相乘生效。接入点:Boss/51job 列表接口 fetch、三平台详情页 goto、
猎聘搜索页 goto。

### 2. 会话批次长休息(utils.SessionPacer)

恒定短节奏(即使带随机)持续数十次仍会被平台统计识别——真人会中途离开/阅读:

- **翻页批次**:每 2~4 页(随机)插入一次 15~40 秒(随机)会话休息;
- **详情批次**:每 8~15 个详情页(随机)插入一次 15~40 秒会话休息
  ——猎聘每岗必开详情,这是其短时触发验证的关键防线。

计数跨任务累计(不重置,只会更保守);长休息可被"停止抓取"打断
(新增 `interruptible_sleep`:分段睡眠每秒检查停止标志)。

### 3. 任务启动预热(utils.warmup)

每个词条组合开始抓取前,载体页先**静默停留 3~8 秒 + 轻滚动 2 次**,模拟真人进入
后先浏览再操作——消除"任务启动瞬间即高频发请求"(短时触发验证的常见诱因)。
接入点:三平台 iter_jobs 开头(Boss/51job 在页面就绪校验后,猎聘在首页 goto 前)。

### 4. 验证通过后冷却

Boss/前程无忧人工验证**通过后先冷却 20~40 秒(随机)再继续抓取**——刚通过验证的
会话被平台重点观察,立即恢复高频极易二次触发;冷却期间响应停止指令。

### 保持不变的原则

- 接口拒绝码(code!=0 / flag!=1)绝不重试连发;
- 验证等待期间绝不刷新页面、绝不发起请求(每 5 秒只读轮询);
- 意外等待静默重试(5 秒观察 + 0~5 秒随机退避,3 次失败自动中止);
- 每平台自身随机间隔(任务级"随机间隔"设置框)继续生效,与上述防线叠加。
