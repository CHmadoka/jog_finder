# 2026-11-08 最近任务滚动懒加载与任务视图表对齐重构

## 背景反馈

1. 最近任务卡片固定 5 条,更早的历史看不到 → 需要**卡片内滚动条 + 触底懒加载**
2. 点"查看关联岗位"进入任务过滤后,右上角**数据表选择器仍停在原选项**——
   列表实际按 task_id 过滤(API 忽略 table_id),选择器显示与数据口径脱节。
   用户指出"任务"与"数据表"两个维度的交互过于杂糅,需要重新考虑

## 设计决策:任务视图 = 叠加在数据表上的"临时镜头"

表选择器保持"数据归属真值"的唯一地位;任务过滤不再与之错位:

- **进入任务视图自动对齐表**:`viewTaskJobs(taskId, platform, tableId)` 新增
  第三参数,三个入口统一传入任务的真实归属表并同步到表选择器——
  岗位详情"来源任务"用 `currentJob.table_id`;任务详情"查看关联岗位"与
  右栏任务下拉用 `filter_snapshot.table_id`;页面刷新恢复(localStorage)
  同一规则。此后"选着表A看着表B的数据"的错位不会再出现
- **任务视图横幅**:任务过滤激活时,工具栏下方显示琥珀色横幅
  (任务号 + 词条/城市 + "切换上方数据表或点右侧退出即回到普通浏览"),
  右侧"退出任务视图"按钮 = clearTaskFilter
- **退出路径收敛为两个且语义一致**:点横幅"退出";切换数据表
  (onTableChange 清 task_id,此前已修)。清空/删除当前表同样退出任务视图
  (任务归属的表不存在了,过滤失去意义)

## 最近任务:滚动懒加载

- 卡片改为 flex 纵向布局:标题固定,`.task-scroll`(flex:1 + min-height:0 +
  `scrollbar-gutter: stable`)行区滚动——沿用左栏"滚动条常驻防宽度跳动"的先例
- 懒加载用 **limit 递增重拉**(5→15→25…,后端 id desc 排序稳定,天然增量、
  无需改接口):滚动距底 24px 时 limit+=10;`done = 返回条数 < limit`;
  底部状态行依次显示"加载中…/已加载全部 N 条/继续下滚加载更早记录"
- `taskList` 状态(loading 防抖)随任务结束的 pollStatus 刷新自动校正
