# 状态区圆点偏高:对齐目标从行盒中心改为汉字字面中心

## 现象

字体混排修复后,视觉反馈"圆点似乎更偏上一点"。

## 实测(Canvas measureText + getBoundingClientRect)

雅黑 13px/600 平台名:基线在行盒顶 +14px(=33),字面 ink ≈
[基线-11, 基线+1.5],**字面中心 ≈ 基线上方 4.75px(28.25)**;
而空闲态行盒中心在基线上方 5.5px(27.5)——圆点此前 `align-self: center`
对齐的是行盒中心,比字面中心偏高约 0.75px。前一轮"零偏移"量的是
字体度量盒(行盒),人眼感知的是实际字形(ink),两者因雅黑汉字
字形在度量盒内偏下而存在系统差。

## 方案对比

- `center + relative top 0.7`:空闲态可达标,但运行态徽章把行盒下方
  撑高(伸至基线下 4.5px vs 平台名 3px),行盒中心随之下移,
  圆点会反向偏低约 0.7px——漂移;
- `baseline + relative top -0.75`:合成基线取圆点边框盒底边,贴基线后
  上移 0.75px,圆点中心恒等于字面中心;**基线锚定**,行盒高低变化
  (空闲/运行态)不产生漂移。margin-bottom 参与不了合成基线对齐
  (实测无效),须用 relative top。

## 修复

`.ts-item .dot { align-self: baseline; position: relative; top: -0.75px; }`

## 验证

刷新页面复测:圆点中心 28.3 vs 字面中心 28.25,偏差 0.05px,
已达渲染精度极限;空闲/运行两态均锚定基线不漂移。
