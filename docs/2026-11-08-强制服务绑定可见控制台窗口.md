# 强制服务绑定可见控制台窗口

## 问题

上一版守卫对"无控制台的分离启动"豁免不启用。实测发现一个漏网形态:
`Start-Process -WindowStyle Hidden` 隐藏启动的实例——
`GetConsoleWindow` 对隐藏窗口同样返回非 NULL 句柄,守卫正常启用,
但 `GetConsoleProcessList` 初始挂载只有 2 个进程(启动器壳+解释器,无 cmd 宿主),
这两个进程只要活着挂载数就永不减少,守卫永不触发。
结果:屏幕上没有任何服务窗口,服务却常驻监听 8765,且没有任何停止入口。

## 修复

`_install_console_binding()` 把"豁免"反转为"强制校验",在启动阶段拦截:

1. 无控制台(`GetConsoleWindow` 返回 NULL,分离/计划任务启动)→ 拒绝;
2. 控制台存在但 `IsWindowVisible` 为 FALSE(隐藏窗口)→ 拒绝;
3. 拒绝时写 `data/app.log` WARNING 并打印原因,`SystemExit(2)` 退出,不留进程;
4. 逃生门:环境变量 `JOB_FINDER_HEADLESS=1` 显式声明后台运行时,跳过校验与守卫;
5. 可见窗口场景守卫不变(CTRL_CLOSE 即退 + 挂载数减少即退)。

## 验证

- 杀掉 0:41 遗留的隐藏实例后,以 `-WindowStyle Hidden` 重启 →
  `app.log` 记录"拒绝启动:控制台窗口为隐藏状态",python 进程即刻退出、无残留;
- `启动.bat` 启动 → 守卫"初始挂载 3 个进程"(cmd+壳+解释器),
  健康检查通过,屏幕可见 job_finder-server 窗口。
