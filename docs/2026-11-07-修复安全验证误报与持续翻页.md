# 2026-11-07 修复安全验证误报;抓取持续翻页至翻完

## 问题与根因

1. **没触发人机验证也弹「需要安全验证」**:
   - 打开岗位的落点判定 `_looks_like_verify` 用了裸 `"security" in url` 子串——
     Boss 正常岗位详情 URL 本身携带防重定向参数 `securityId=...`,
     导致**每个正常岗位打开都被误判为验证页**并弹提示;
   - 抓取流程的 `_is_verify_page` 还会用「验证码」等词匹配**页面标题**,
     安全类岗位(标题含"验证码")会被误判,任务被错误中断。
2. **抓取提前停止**:三个平台的翻页循环都有
   「整页岗位全部与先前重复 → 停止翻页」的启发式;但页与页之间因排序
   微调常有重叠,整页重复 ≠ 结果翻完,导致设定页数没用完就提前结束。

## 变更清单

- `app/browser/manager.py` `_looks_like_verify`:只认验证页路径特征
  (`_security_check` / `security-check` / `/verify` / `verify.html`)与
  标题「安全验证/安全挑战」,去掉裸 `security`/`verify` 子串。
- `app/platforms/boss.py`:
  - 标题判定拆出 `_VERIFY_TITLE_RE`(仅 安全验证|安全挑战),
    「拖动滑块/验证码」只用于正文判定;
  - 新增详情页 DOM 结构防线:存在 `.job-sec-text/.job-banner/.job-scribe/
    .detail-content` 区块即非验证页(验证页只替换内容不改 URL,但不会
    伪造详情页区块)。
- `app/platforms/{boss,liepin,job51}.py` `iter_jobs`:移除
  「无新岗位即 break」;停止条件仅剩——搜索结果翻完(Boss 以 `hasMore=false`
  为准)/ 达到设定页数上限 / 手动停止 / 异常中断。

## 验证

- 断言脚本(10 项):带 securityId 的正常岗位 URL 不误判;真验证 URL/标题
  仍命中;有详情 DOM 的页面不误判;短正文含验证词命中;长正文(正常 JD)
  不误判。全部通过。
- unittest 64 项通过;服务已重启生效。
