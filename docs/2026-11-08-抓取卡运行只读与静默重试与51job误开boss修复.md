# 抓取卡运行只读与意外等待静默重试与 51job 误开 Boss 修复

日期:2026-11-08

## 需求与兼容性判断

1. **任务进行中,对应平台的抓取卡片只读**。
2. **意外等待静默重试**:抓取中可能出现风控未识别、中断、无响应、反复重试;
   意外等待期间不反复刷新页面,每超过 5 秒附加随机 0~5 秒静默后再尝试一次,
   连续 3 次失败自动中止任务。
3. **前程无忧点击抓取会先打开 Boss,修复**。

与现状的兼容性结论(先判断再动手):

| 场景 | 原状 | 判断 |
|---|---|---|
| Boss 列表接口 fetch 异常 | 3 次尝试、固定 1.5s 间隔 | 次数兼容,间隔需改静默退避 |
| 三平台详情页落地等待 | 8 轮 × ~2s 轮询,失败仅"跳过" | 已"不刷新页面",节奏需放缓、需按 3 次中止 |
| 51job 接口失败 | 2 次失败中止、间隔 human_delay | 次数需统一为 3 |
| 猎聘响应捕获失败 | 直接 DOM 兜底,无重试 | 缺静默重试,需补 |
| 验证页/人工介入 | 立即 AntiBot 中止 | 兼容,保留(非意外等待) |
| 页面被关看门狗重开 | 5s 节流 | 兼容,保留(保命机制) |

现有代码已确立"失败不硬闯、不反复刷新"原则,无主动反复 reload 的循环 —— **兼容**,
做统一升级而非推翻。

## 实现

### 静默重试工具(app/utils.py)

统一节奏常量:`RETRY_UNIT=5.0`、`RETRY_ATTEMPTS=3`。

- `silent_backoff()`:静默等待 `5 + rand(0~5)` 秒(= 5 秒观察 + 0~5 秒随机退避),
  全程不做任何导航/刷新;
- `patient_poll(check)`:静默观察式等待,每轮静默后执行一次 check(),3 轮全失败返回
  False;check 抛出的异常(风控判定)原样上抛;
- `patient_call(op)`:静默重试包装,失败后静默 5~10s 再试同一操作,最多 3 次,
  返回 (ok, 结果/最后异常);业务性拒绝(接口拒绝码)作为正常返回值不走重试;
- `page_responsive(page)`:页面是否仍可响应(标题非空且脚本可执行),
  用于区分"无响应/被清空"与"正常重定向"。

### 平台应用

- **Boss**:`_fetch_joblist` 瞬态异常改走 `patient_call`(拒绝码仍不重试连发);
  详情落地轮询(8×2s)改为 3 轮静默观察(每轮 5~10s),3 轮不落地时分级:
  页面无响应/被清空 → AntiBot **自动中止任务**;平台正常响应但岗位失效 → 维持
  "已下线跳过"。
- **51job**:接口失败阈值 2→3(统一 RETRY_ATTEMPTS),间隔由 human_delay 改静默
  退避;详情落地同 Boss 分级处理。
- **猎聘**:goto+expect_response 捕获失败不再立即 DOM 兜底——静默 5~10s 后重试
  同一页,最多 3 次;仍失败且页面无响应 → AntiBot 中止,页面正常 → DOM 兜底;
  详情落地同上分级。
- 接口拒绝码(flag!=1 / code!=0)维持"绝不重试连发"哲学,不受影响。

### 51job 误开 Boss 修复(根因)

`browser_manager.ensure()` 无参调用时,冷启动首屏硬编码 `zhipin.com`(作为
cookie 载体的历史兜底)。点击前程无忧抓取时(check_login / 调度器 _run),若浏览器
未运行,冷启动先开 Boss 再开 51job。修复:全部 4 处调用点
(`tasks.check_login`、调度器 `_run`/`_run_refresh`、`diagnose_open`)显式传入
`plat.home_url`,冷启动首屏直达目标平台首页。

### 抓取卡运行只读(web)

当前平台任务运行中(`running`)时,左栏抓取卡全部输入禁用:存入数据表、随机间隔
双输入与复位按钮、快速/已存条件模式切换(加 disabled 态样式)、岗位设置、
城市选择(CityPicker 组件新增 disabled prop,级联与标签删除一并禁用)、翻页数
(两处)、薪资双输入。停止按钮保持可用。
