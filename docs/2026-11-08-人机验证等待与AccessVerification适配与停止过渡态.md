# 人机验证强提醒等待、Access Verification 适配与停止过渡态

日期:2026-11-08

## 需求

1. **普通人机验证**:强提醒并持续等待,每 5 秒轮询一次是否通过验证,
   **绝不刷新页面、绝不发起任何请求**;通过后任务自动继续。
2. **前程无忧人机验证(Access Verification)适配**(实测触发)。
3. **点击中止后按钮不马上复原、最近任务仍显示"进行中"**——排查是否因
   "没有终止时间"导致误判,并修复反馈缺失。

## 根因分析(问题 3)

- 点击「停止抓取」只是设置停止事件:适配器要等**当前阻塞操作**(详情导航最长
  25s / 静默观察最长 30s / 猎聘响应等待 20s)到达检查点才真正退出;
- 退出前 DB 任务行 status 仍为 running → 最近任务显示"进行中";
- `finished_at` 仅在 `done` 时写入是**有意设计**(中断/中止任务无完成时间),
  不是误判根源;根源是缺少"停止中"过渡态,表现为"点了没反应"。

## 实现

### 人机验证等待(Boss / 前程无忧)

- `app/utils.py` 新增验证等待标志注册表 `set_verify_wait/is_verify_wait`
  (平台级,与运行时延迟注册表同风格)。
- **Boss** `_wait_manual_verify` 重写:不再立即中止任务——强提醒(progress 常驻
  ⚠ 文案)后进入持续等待循环:**每 5 秒只读轮询**一次页面是否已通过验证
  (`_is_verify_page` 读 URL/标题/DOM,不产生任何平台请求),绝不刷新/重新导航;
  通过后自动继续原流程(详情解析/接口拉取)。等待期间每轮响应停止指令。
- **前程无忧** `_raise_if_verify` → `_wait_if_verify`:检测到验证页(特征新增
  **Access Verification**,正则 `access\s*verification`)不再直接中止,同样
  强提醒 + 5 秒只读轮询等待;搜索页与详情页两处调用点统一接入。
- **猎聘**维持"短信验证立即中止"现状(账号行为异常属强校验,非普通滑块)。
- `_parse_detail`(Boss/51job)增加 `progress` 参数,等待提醒可达;补全任务
  (`_run_refresh`)同步传入。
- 调度器 `_run`/`_run_refresh` 的 `except AntiBot`:若停止指令已置位(用户在
  等待验证期间点停止)→ 按手动停止收尾(status=stopped),不写风控错误、不弹窗。

### 停止过渡态与强提醒透出

- `/tasks/status` 每平台新增 **`stopping`**(停止指令已发出、任务未退出)与
  **`verify_wait`**(正处于等待人工验证循环),全平台统一透出。
- 前端:
  - 抓取按钮:`stopping` 时立即切为「停止中…」并禁用(防重复点击),消除
    "点了没反应"的观感;任务真正退出后复原为「开始抓取」;
  - 最近任务行:运行中 + 停止指令已发出 → 标签「停止中」+ 文案"正在停止,
    等待当前操作结束…";任务下拉候选/任务详情/任务管理表同步;
  - 顶栏状态卡:stopping 时进度前缀「⏹ 停止中·」;
  - **人机验证强提醒**:`verify_wait` 上升沿弹 `ElNotification`(warning,
    不自动关闭),说明"请在浏览器完成验证,通过后自动继续"。

## 验证

- `py_compile` + `import app.main` + `node --check` 通过;
- 冒烟:`status()` 全平台含 stopping/verify_wait 且空闲恒 False;
  `set_verify_wait` 置位后 `verify_wait` 正确透出;
- `unittest discover tests`:95 个测试全部通过。
