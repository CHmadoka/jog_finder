# README 补充搜索与判定规则

日期:2026-11-07

## 背景

README 的「筛选条件说明」只写了档位/条件/行业偏好三段,且有几处已过时:
- 提到「筛选条件 = 平台 + 城市 + 档位 + **关键词**」,但限定词条功能已移除;
- 备注格式示例与实际实现不符(实际是 `契合: … | 不符: …` 分段);
- 没有说明哪些判定会拦截入库、哪些只写备注——这是最容易误解的点;
- 契合/不符由谁决定、不配 LLM 会怎样,完全没写。

## 改动

新增 **「搜索与判定规则」** 章节,共九节,全部与源码对齐并经实测验证:

1. **搜索:一次任务搜什么** — 组合式检索公式
   `档位全部词条 × 选中城市`,无"只跑一个词条"入口,城市未收录则启动前拒绝
2. **搜索:单个组合内怎么翻页** — 页数上限、整页重复继续翻、列表阶段薪资过滤
   (含 `15-25K`/`1.5-2.5万`/`30-60万/年`/`面议` 的解析对照表)、详情前查重、三平台检索方式差异
3. **判定:单个岗位能不能入库** — 六步顺序表(下线 → 被拦截 → 查重 → 活跃度 → 备注 → LLM),
   明确只有活跃度会拒绝入库
4. **活跃度窗口** — `…后`/`…前`/`…活跃`/无后缀 四种后缀的方向语义与判定差异,
   以及 1 分钟容忍的由来
5. **行业偏好** — 避开优先于优先的三种结果,`电.{0,2}商` 跳字匹配原理
6. **关键词规则引擎** — 11 条正文 + 2 条标题规则的完整对照表,加软提示说明
7. **LLM 分析** — 触发条件、输入内容、输出 JSON、对 fit/score/remarks 的影响、
   以及未配置时 `fit` 为空的重要提示
8. **备注格式** — 分段拼接规则与实例
9. **完整判定链路** — 一张流程图汇总

同时修正:
- 功能特性里的档位说明补「一次任务跑全部词条」,并加指向新章节的链接;
- `.env` 表格注明本仓库实际窗口是 30 天、LLM 任一为空即禁用;
- 使用流程第 3/5 步去掉关键词、注明条件必须关联档位;
- 架构章节细化 `app/filter/` 三个文件各自的职责;
- 常见问题补三条:没有契合/不符标签、被判不符却没拦掉、跳过原因含义;
- 删掉与新章节重复的 Boss 接口直连说明块(内容并入平台差异表)。

另修正界面文案:统计条「契合」的悬停提示原为"契合判定依赖筛选引擎/LLM",
实际只有 LLM 决定,改为"契合/不符由 LLM 判定;未配置 LLM 时该标记为空,这些岗位不计入两侧"。

## 验证

- 13 条关键词规则逐条实测命中预期文本;
- 行业跳字匹配实测:`电子商务` 命中 `电商`、`医疗服务` 命中 `医疗`;
- 薪资过滤实测 8 组(含单边范围、万/年薪折算、面议不误杀);
- 备注拼接实测:`契合: 行业契合: 医疗服务 | 不符: [加班] …;[压力] …`;
- LLM 未启用时确认 `fit=None`、`fit_score=None`;
- README 全部内部锚点校验通过;`node --check` 通过。
