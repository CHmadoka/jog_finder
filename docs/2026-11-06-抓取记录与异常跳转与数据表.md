> 两个 python.exe 属正常现象(父子关系,仅子进程监听端口)。

## 变更总览

1. **登录检查**:抓取与"补全HR活跃"任务启动前都会校验目标平台登录态;job51/猎聘增加
   "请登录/游客"文案兜底判定(登录入口选择器失效时不再误判)。未登录直接中止并记入异常面板。
2. **字段异常全量记录**:各平台列表/详情解析出现的字段缺失(缺职位名、缺描述、缺活跃文案、
   接口改版信号、详情提取异常等)统一计入抓取异常面板;每条异常携带相关岗位链接,
   点击即在已登录浏览器中打开(新增 `POST /api/events/{id}/open`)。
3. **跳过原因**:跳过仍属正常过滤逻辑,不并入异常,但原因已可解释——
   任务结束时消息附原因明细(已存在/活跃度窗口/已下线/被平台拦截/同轮重复),
   运行状态区"跳过"计数旁同步展示,并落库 `crawl_task.skip_stats`。
4. **抓取记录完善**:`crawl_task` 新增专用列 `keywords`(全部词条,以 `|` 分隔)、`city`、
   `salary_range`(存用户输入原文,如 `10-20` / `10,` / `,20`,单边可缺省)、`skip_stats`;
   `finished_at` 语义改为"完成时间":仅 `done` 时写入,为空即意外中断或中止。
   `job` 新增外键 `crawl_task_id`(产生/最后更新该岗位的抓取,有字段更新时刷新)。
5. **薪资范围条件**:快速抓取与已存条件(存于 extras.salary)均可配置薪资范围(K/月);
   列表阶段直接过滤范围外岗位,不打开详情页(解析失败的薪资不误杀)。
   历史 `crawl_task` 的词条/城市从快照自动回填。
6. **最后更新时间**:岗位列表/详情/导出的"入库时间"统一改为"最后更新时间"(`updated_at`),
   列表默认按其倒序(`first_seen_at` 仍在库内保留,不再对外展示)。
7. **Web 列调整**:删除"判定"列;统计条移除"未分析""HR在线"两个按钮(契合/不符保留,
   判定筛选不再提供"未分析"选项);列表行删除按钮修复(改为确认弹窗,原 popconfirm
   与 tooltip 嵌套导致点击无效)。
8. **分类排列**:城市、经验/学历、HR活跃(及最后更新)列表头可点击排序(分类归组,
   组内按最后更新倒序);工具栏提供"↓ 降序/↑ 升序"切换开关;HR活跃按估算时间前缀排序。
9. **数据表**:新增 `job_table`(id/表名/标识符),岗位与抓取目标可归属不同表;
   默认表(id=1"默认表")不可删除,删除其它表时其岗位自动归入默认表。
   入口:"管理与工具 → 数据表管理";抓取面板可选"存入数据表",岗位工具栏可按表筛选。

## 主要代码改动

- `app/models/entities.py`:`JobTable` 新实体;`Job.crawl_task_id/table_id`;
  `CrawlTask.keywords/city/salary_range/skip_stats`;`AppEvent.url`。
- `app/models/database.py`:列迁移 + 默认表种子 + 历史任务快照回填。
- `app/platforms/common.py`:`parse_salary_k / parse_salary_range / salary_in_range`
  (薪资文本→K/月区间;范围原文解析;交集判定,解析失败返回 None 不误杀)。
- `app/platforms/{boss,job51,liepin}.py`:登录兜底判定、字段异常上报(回调/`_warnings`)、
  列表阶段薪资过滤。
- `app/scheduler/runner.py`:任务条件列写入、跳过原因统计、事件携带链接与级别、
  补全任务登录检查、入库/更新时写 `crawl_task_id` 与 `table_id`。
- `app/api/{tables(新),tasks,jobs,events,export}.py`:数据表 CRUD、任务参数透传、
  排序参数(`sort_by/sort_order/table_id`)、异常跳转、导出时间列调整。
- `web/{index.html,app.js}`:上述界面变更;跳过原因提示;异常点击跳转。
