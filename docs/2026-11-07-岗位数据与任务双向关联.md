# 岗位数据与抓取任务双向关联

日期:2026-11-07

## 背景

数据层本就有关联:`job.crawl_task_id`(外键,语义"产生/最后更新该岗位的
抓取任务",入库写入、旧岗位被新任务更新字段时刷新),`JobOut` 也已返回。
但界面与查询完全未暴露:任务详情只有统计计数,看不到对应数据;岗位上看
不到来源任务;也无法按任务检索。

## 改动

- `app/api/jobs.py`
  - `_filtered_query` 新增 `task_id` 参数(按 `crawl_task_id` 过滤);
    任务过滤时**忽略 table_id**——任务当时存入的表未必是当前工作表,
    "查看某次任务的数据"不应被当前表选择截断。
  - `/jobs`(列表)与 `/jobs/stats`(统计)均支持 `task_id`,口径一致。
- `web/index.html`
  - 任务详情卡片:新增「查看关联岗位」按钮,跳转右栏按任务过滤。
  - 岗位详情抽屉:新增「来源任务」项,显示任务号,点击同样跳转
    (早期无任务记录的数据显示占位说明)。
  - 右栏筛选区:任务过滤激活时显示「任务 #N 的关联岗位」可关闭标签,
    并提示已忽略工作表筛选。
- `web/app.js`
  - `query.task_id` 状态;`loadJobs/loadStats` 传参(任务过滤时不再传
    table_id);`viewTaskJobs(taskId, platform)`(联动平台、关闭弹窗、
    回到第 1 页)与 `clearTaskFilter()`;切换平台时自动退出任务过滤。

## 验证

- 68 项测试全部通过;`node --check` 与 py_compile 通过。
- 存量数据核查:771 条岗位 `crawl_task_id` 全部指向任务 #35,无空值。

## 备注

- 需重启服务生效(关闭 job_finder-server 窗口后重新运行 启动.bat)。
- "关联岗位"的口径:本任务**新入库**或**被本任务更新过字段**的岗位
  (与 crawl_task_id 的"最后更新"语义一致,可能大于任务卡片里的"新入库"数)。
