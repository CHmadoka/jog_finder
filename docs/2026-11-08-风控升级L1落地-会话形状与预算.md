# 风控升级 L1 落地:会话形状修复 + 单会话预算 + 触发后降档

日期:2026-11-08
依据:`docs/2026-11-08-风控升级报告.md`(同日评审)。本篇是 L1 路线图(§五)的落地实现,
并顺带包含两项低成本的 L2 项(PV 配平、鼠标轨迹)与一个 HEAD 既有 bug 修复。

## 核心思路

风控判定的是**会话形状**而非单点频率:此前所有随机化都押在"速率"维度(uniform 平顶
分布反而自证自动化)。本次把伪装升级到分布/语义/结构三个维度,同时用**预算**把
"一次抓完"改为"分批像人一样抓",消除账户基线偏离这个最大风险源。

## 改动清单

### 1. 人类化间隔分布(`app/utils.py` `_human_gap`)

- `human_delay`/`detail_delay` 弃用 `random.uniform(lo, hi)`(平顶直方图,KS 检验
  一测即中),改**对数正态采样**:几何中位数 `sqrt(lo*hi)`、sigma 按区间比值推导,
  约 10% 样本钳回下限(形成"反应下限"点质量),多数靠近下限=真人快速连续操作;
- 6% 概率注入长尾(uniform(hi, min(hi*4, 90s)),模拟真人读长内容/离开片刻;
- 硬下限仍为 lo(用户设置的间隔下限承诺不变)。

### 2. 危险率会话休息(`SessionPacer` 重写)

- 固定批长(每 2~4 页/每 8~15 详情)会产生可统计的**元周期**;改为**无记忆几何
  触发**:每页/每岗以 `1/平均批长` 的概率触发休息(翻页 1/3、详情 1/11.5),
  实测 300 tick 触发 105 次(≈期望);
- 休息时长改对数正态,钳制 `[idle_lo, min(idle_hi*3, 120s)]`。

### 3. 详情页 referer 链(三平台 `_parse_detail`)

- 详情页 goto 携带 `referrer=当前搜索列表 URL`(此前 100% 直达入口、referer 断裂
  是强自动化签名;Boss 的 `open_url_native` 人工打开场景早有此做法,本次对齐到批量抓取);
- 来路 URL 由任务上下文 `_search_ctx` 携带(猎聘/前程无忧每页更新,Boss 按
  词条+城市构造 `/web/geek/job?query=...&city=...`);无上下文时回退平台首页。

### 4. 详情页阅读仿真(`utils.human_read` 新增)

- "落地即抽 DOM 立即离开"= 零阅读访问(停留与内容长度完全无关)——强签名;
- 新增 `human_read(page, text, t0)`:目标停留 ∝ 描述长度(对数正态,
  `3 + 1.2*ln(1+len)` 秒,钳制 4~24s),穿插 2~4 次滚动;**解析/落地校验耗时计入
  停留,只补差额**——不为凑时长空转(效率优先),描述极短或解析耗时已超目标时零开销;
- 三平台 `_parse_detail` 末尾接入(Boss/猎聘每岗生效,前程无忧仅描述缺失兜底时生效)。

### 5. 鼠标轨迹仿真(`utils.human_scroll` 增强)

- wheel 前先产生两段多步插值 `mouse.move`(mousemove 轨迹)——没有轨迹历史的受信
  滚轮事件是可识别签名;大概率向下浏览,偶尔回看上文(负向滚动)。

### 6. 遍历语义打乱

- `runner._run`:词条×城市 combos **shuffle**(有序笛卡尔积穷举是机器签名;
  打乱不影响覆盖,全部组合仍被处理);
- 三平台:列表内新岗位 `fresh` **shuffle**(不再按排序顺序逐条开详情)。

### 7. 单会话安全预算(`SessionBudget` 新增 + 三平台接入)

- `config.SESSION_PAGE_BUDGET=40` / `SESSION_DETAIL_BUDGET=120`(`.env` 可覆盖):
  单登录态列表页/详情页请求上限——真人日浏览量有限,短时数百上千次请求无论间隔多
  随机都显著偏离账户历史分位(实测 Boss ~1 条/秒×800+ 条 → 403 code=32);
- 预算对象由调度器构造、经 `extras` 内存注入适配器(不进快照/DB);达限抛
  `BudgetExhausted`(base.py 新增),`runner` 捕获后按 **done(非错误)** 收尾:
  已抓数据完整保留,剩余岗位下次任务自动继续(已入库自动跳过,重复成本为零);
- 计数点:Boss/猎聘/前程无忧翻页成功各计 1 页,三平台详情打开前各计 1 个
  (前程无忧常规零详情,仅兜底路径计数);补全/旧数据修复路径无预算、不受影响。

### 8. PV 配平(打断"纯 API 会话"形状)

- Boss `iter_jobs`:每 3~6 个接口页把载体页真实导航回**首页**一次(PV+平台埋点噪声;
  首页无搜索接口轮询,不与 fetch 叠加——保持原先"不长期停留搜索页"的实测结论),
  停留 4~9 秒+轻滚动;
- 前程无忧新增 `_fetch_via_page_pv`:每 3~6 页**导航到真实搜索页并捕获页面自身发出的
  签名请求**取数(页面自己的请求天然合法,冷启动已有同款先例),失败自动回退页内
  fetch——净请求数不变,API 请求从此伴生页面浏览。

### 9. 触发后降档(`runner.start`)

- 风控是累积风险分:刚触发过的账号被重点观察。任务启动时统计该平台近 24h 风控事件
  (异常面板中含"风控/访问受限/安全验证"的记录):1 次 → 预算减半;2 次 → 减到 1/4;
  **≥3 次 → 拒绝启动**(提示冷却 48h,可在异常面板清除记录后强制重试);
- 降档系数与事件数写入任务快照(`budget_scale`/`risk_hits_24h`)供追溯。

### 10. 效率提升(与防风控并行不悖)

- **Boss 探测页复用**:原流程对第 1 页请求两次(可用性探测 + 正式拉取);有词条时
  两者同参数,现直接复用探测结果——每词条组合省 1 次接口请求与 1 次风控暴露;
- 预算止损:达阈值立即收尾,不再产生注定撞限流页的无效请求(此前被限流后每 ~5 秒
  撞一次的循环已由既有防线杜绝,预算进一步把"边缘请求"降到零);
- 阅读仿真按"补差额"实现,解析快的页面几乎零额外开销。

### 11. Bug 修复(HEAD 既有)

- 猎聘 `_parse_detail` 签名缺 `progress` 参数但函数体 `tick(progress=progress)`
  引用它——每个猎聘详情都会 NameError 崩溃(9229317 引入,未被测试覆盖,因测试
  不触达该方法)。本次补上参数并在调用点传入。
